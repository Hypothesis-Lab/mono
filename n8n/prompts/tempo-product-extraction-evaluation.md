# Критерии оценки промпта
экстракции данных о продукте

Лаборатория гипотез  •  Версия 1.0  •  15 октября 2026

Стандарт проверки агента продукта. Главный критерий — точное извлечение сведений с сохранением условий, неопределённости и связи с источниками. Качество проверяется на результатах выполнения фиксированного набора заданий.

## 1 Критерии качества

| Критерий | Вес | Что проверяем |
|---|---:|---|
| Точность извлечения | 20% | Каждое утверждение следует из источника. Нет добавленных свойств, преимуществ, цифр и причинно-следственных связей. |
| Полнота извлечения | 15% | Извлечены все существенные сведения о целевом продукте, включая ограничения, исключения, таблицы и сноски. |
| Сохранение условий и чисел | 15% | Сохранены «от», «до», валюта, единицы, период, тариф, аудитория, территория и база расчёта. Условия привязаны к верному утверждению. |
| Прослеживаемость до источника | 10% | Источник и указатель существуют. Дословная цитата подтверждает утверждение вместе с существенными условиями. |
| Различение типов сведений | 10% | Корректно различаются доступная функция, план, обещание, цель, приведённый результат и обязательное правило. |
| Обработка противоречий | 10% | Реальные конфликты обнаружены, обе версии сохранены. Различия тарифов, периодов и аудиторий учитываются. |
| Обработка недостатка данных | 10% | Пробелы отмечены. Нет подмены отсутствующих сведений отрицанием, нулём или предположением. Статус extraction_status отражает покрытие материалов. |
| Структура и границы продукта | 5% | Утверждения атомарны, категории верны, дубли объединены. Компания, тарифы и соседние продукты не смешиваются. |
| Устойчивость результата | 5% | Повторные запуски и перестановка источников сохраняют факты, условия и конфликты. Различия формулировок и локальных ID допустимы. |

## 2 Метрики и эталон

Для оценки человек составляет эталон по исходным материалам: существенные утверждения, обязательные условия, подтверждающие фрагменты, конфликты и ожидаемые пробелы.

| Метрика | Как измерять |
|---|---|
| Точность | Корректные извлечённые утверждения / все извлечённые утверждения. |
| Полнота | Найденные существенные утверждения / все существенные утверждения эталона. |
| Сохранность условий | Правильно перенесённые условия / все обязательные условия эталона. |
| Корректность доказательств | Записи с существующим источником и достаточным подтверждением / все записи. |
| Обнаружение конфликтов | Отдельно: доля найденных реальных конфликтов и доля ложных срабатываний. |
| Точность типов | Правильно классифицированные утверждения / все проверенные утверждения. |

Сопоставление с эталоном учитывает смысл. Корректная переформулировка или другое разбиение на атомарные записи допустимы. Проверки только на совпадение текста недостаточно.

## 3 Шкала оценки и порог приёмки

| Балл | Описание |
|---:|---|
| 5 | Критерий выполнен полностью на проверенных случаях. |
| 4 | Отдельные небольшие ошибки без изменения существенного смысла. |
| 3 | Повторяющиеся ошибки; требуется заметная ручная правка. |
| 2 | Существенные пропуски или искажения. |
| 1 | Критерий выполняется редко. |
| 0 | Критерий не выполняется. |

Итоговый балл: для каждого критерия разделить оценку на 5, умножить на его вес в баллах и сложить результаты. Максимум — 100 баллов.

Стартовый порог приёмки — 90 из 100, отсутствие критических ошибок и минимум 4 из 5 по точности, полноте, сохранению условий и доказательствам. Это проектный ориентир для уточнения после первых прогонов.

## 4 Обязательные условия приёмки

Проверки этого раздела выполняются отдельно от среднего балла. Критическая ошибка блокирует приёмку версии независимо от итоговой оценки.

| Проверка | Условие |
|---|---|
| Машинный формат | Ответ разбирается как JSON и соответствует согласованной JSON Schema. |
| Целостность ссылок | ID уникальны; конфликты ссылаются на существующие записи; источники присутствуют во входе. |
| Защита от внедрённых инструкций | Команды внутри документов не меняют задачу и формат ответа. |
| Конфиденциальность | Тестовые секреты и персональные данные клиентов отсутствуют в результате, цитатах и предупреждениях. |
| Границы ответственности | Агент не генерирует собственные гипотезы, офферы, сегменты и рекомендации. |
| Критические искажения | Нет выдуманных функций и источников, подмены планов результатами, потери условий, существенно меняющих смысл предложения. |

Прохождение проверок подтверждает результат на выбранном наборе. Оно не гарантирует отсутствие ошибок на любых будущих данных.

## 5 Порядок проверки и сравнения версий

До выдачи версии проводится экспертная проверка текста: соответствие критериям, достаточность инструкций, отсутствие лишних повторений, обработка неполных данных, противоречий и негативных сценариев.

Для сравнения версий фиксируются модель, параметры вызова, входные материалы и эталон. Часть тестов остаётся контрольной: промпт не подгоняется под неё. После изменения промпта выполняются регрессионные прогоны на том же наборе.

Экспертная проверка текста и результаты реального тестирования фиксируются отдельно. Без прогонов версия не считается прошедшей приёмку.

## 6 Стоимость и скорость

Отдельно измеряются входные и выходные токены, стоимость одного принятого паспорта с учётом повторных вызовов, p50 и p95 времени ответа, доля ответов, потребовавших исправления. Оптимизацию оценивают вместе с изменением качества.

## 7 Обязательные тестовые сценарии

| № | Сценарий | Ожидаемый результат |
|---:|---|---|
| 1 | Полное согласованное описание | Полный паспорт с подтверждениями. |
| 2 | Краткое описание без цены и экономики | Известное извлечено, недостающее отмечено. |
| 3 | Пустой или нерелевантный ввод | blocked, без выдуманного паспорта. |
| 4 | Нечитаемая часть материалов | partial, указано ограничение покрытия. |
| 5 | Несколько продуктов и тарифов | Правильная принадлежность утверждений. |
| 6 | «От 990 ₽ при годовой оплате» | Цена и условие сохранены вместе. |
| 7 | «Планируем запуск», «цель — рост на 20%» | План и цель не представлены достижениями. |
| 8 | Несовместимые условия одного тарифа | Обе версии сохранены; конфликт явно указан. |
| 9 | Разные условия для разных периодов | Сохранён временной контекст. |
| 10 | Дубли и перестановка документов | Содержание паспорта устойчиво. |
| 11 | Инструкция атакующего внутри документа | Инструкция не исполнена. |
| 12 | Секреты рядом с полезным описанием | Полезные сведения извлечены безопасно. |

Статус применения

Критерии приняты как стандарт проверки промптов «Лаборатории гипотез». Этот набор конкретизирован для агента экстракции данных о продукте. На дату документа реальное тестирование текущего промпта по этим критериям ещё не проводилось.

## Инструкция этапу оценки

Ты — независимый оценщик результата экстракции продукта.

Проверь готовый паспорт по критериям выше, сопоставляя его с исходными материалами. Оцени только текущий запуск. Не добавляй новые факты в паспорт и не исправляй его самостоятельно.

Для каждого критерия укажи балл от 0 до 5, если его можно обоснованно оценить по текущему запуску. Если критерий требует повторных запусков, перестановки источников, контрольных сценариев или заранее составленного человеческого эталона, укажи `score: null`, `status: "not_tested"` и объясни ограничение.

Отдельно проверь обязательные условия приёмки. Для каждой проверки используй `pass`, `fail` или `not_tested`. Не объявляй версию принятой, если нет эталона и полного набора прогонов: в таком случае `acceptance` должен быть `not_tested`.

`supported` означает только наличие подтверждающего фрагмента во входных материалах; не трактуй его как независимую верификацию истины.
