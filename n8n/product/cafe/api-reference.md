# API Tempo

Все даты передаются в формате ISO 8601; идентификаторы — строки.

## Общие правила

- Базовый URL: `https://api.tempo.ru/v1`
- Формат тела: JSON (`application/json`).
- Все запросы требуют `Authorization: Bearer <token>`.
- Часовой пояс расписания задаётся точкой; примеры используют `Europe/Moscow`.
- API не создаёт расписание автоматически и не проверяет трудовое законодательство.

## `GET /locations/{location_id}/shifts`

Возвращает смены точки за диапазон дат. Обязательные query-параметры: `from`, `to` в формате `YYYY-MM-DD`.

Пример ответа:

```json
{
  "data": [
    {
      "id": "sh_204",
      "location_id": "loc_12",
      "employee_id": "emp_31",
      "role": "barista",
      "starts_at": "2026-10-20T08:00:00+03:00",
      "ends_at": "2026-10-20T16:00:00+03:00",
      "status": "published"
    }
  ]
}
```

## `POST /locations/{location_id}/shifts`

Создаёт одну смену. Обязательные поля: `employee_id`, `role`, `starts_at`, `ends_at`. Новая смена имеет статус `draft` и не видна сотруднику до публикации расписания.

Успешный ответ: `201 Created` с объектом смены и `status: "draft"`.

## `POST /shift-requests`

Создаёт запрос сотрудника. Обязательные поля: `type` (`time_off` или `swap`), `shift_id`; для `swap` также требуется `target_shift_id`.

Новый запрос имеет статус `pending`. Отправка запроса **не меняет расписание**.

## `POST /shift-requests/{request_id}/decision`

Решение управляющего. Тело: `{ "decision": "approved" }` или `{ "decision": "rejected" }`.

При одобрении обмена расписание обновляется. При отклонении расписание не меняется.

## Коды ошибок

- `400` — некорректное тело или дата окончания не позже даты начала.
- `401` — отсутствует или недействителен токен.
- `403` — у пользователя нет доступа к точке или действию.
- `404` — точка, смена или запрос не найдены.
- `409` — конфликт состояния, например запрос уже обработан.

## Не описано / не поддерживается

API не поддерживает пагинацию, webhooks, OAuth, синхронизацию с кассами и передачу данных фактического учёта рабочего времени. Лимит запросов составляет 60 запросов в минуту на токен.
