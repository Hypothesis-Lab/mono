# API Lumen

Этот документ описывает интеграционные методы для мобильного приложения, продуктовых экранов и статусов заявки. Полные условия кредитования и публичная доступность API определяются договором интеграции и не заменяются этим справочником.

## Общие правила

- Базовый URL внутреннего API: `https://api.lumen-bank.ru/v1`.
- Формат тела: JSON (`application/json`).
- Идентификаторы — строки; суммы — целые значения в копейках.
- Все даты и время передаются в ISO 8601 с часовым поясом.
- Каждый запрос требует токен клиента или сервиса с правом доступа к конкретной карте.
- Для операций создания используется `Idempotency-Key`.
- API не принимает решение о кредитовании на стороне клиента и не позволяет обойти проверку банка.

## `GET /cards`

Возвращает карты текущего клиента без чувствительных реквизитов.

```json
{
  "data": [
    {
      "id": "card_204",
      "type": "debit",
      "program": "salary",
      "status": "active",
      "masked_pan": "•••• 1234",
      "credit_limit_status": "not_connected"
    }
  ]
}
```

Поддерживаемые значения `program`: `debit` и `salary`. Полный номер карты, PIN и CVV не возвращаются.

## `GET /cards/{card_id}/credit-limit/eligibility`

Возвращает предварительную доступность сценария подачи заявления. Ответ не является кредитным решением.

```json
{
  "card_id": "card_204",
  "eligible_for_application": true,
  "checks": [
    {"code": "existing_lumen_bank_card", "status": "passed"},
    {"code": "supported_mobile_app", "status": "passed"}
  ],
  "disclaimer": "Предварительная проверка не гарантирует одобрение"
}
```

Возможные статусы проверки: `passed`, `failed`, `unknown`, `requires_action`.

## `POST /cards/{card_id}/credit-limit/applications`

Создаёт заявление на подключение кредитного лимита.

```json
{
  "requested_limit": 7500000,
  "currency": "RUB",
  "channel": "mobile_app",
  "consents": {
    "terms_reviewed": true,
    "data_processing": true
  }
}
```

`requested_limit` передаётся в копейках. Допустимый диапазон желаемого лимита — от 3 000 000 до 10 000 000 копеек. Запрос `201 Created` означает регистрацию заявления, а не одобрение.

Пример ответа:

```json
{
  "id": "cla_901",
  "card_id": "card_204",
  "requested_limit": 7500000,
  "currency": "RUB",
  "status": "submitted",
  "created_at": "2026-10-18T10:14:00+03:00"
}
```

## `GET /credit-limit/applications/{application_id}`

Возвращает статус заявления.

| Статус | Значение |
|---|---|
| `draft` | Заявление начато, но не отправлено |
| `submitted` | Заявление отправлено в банк |
| `in_review` | Заявление рассматривается |
| `approved` | Банк одобрил подключение лимита |
| `rejected` | Банк отказал в подключении или не предоставил лимит |
| `cancelled` | Заявление отменено до принятия решения |

Ответ `approved` должен содержать предоставленный лимит только после публикации решения клиенту. `requested_limit` и `approved_limit` — разные поля.

## `POST /credit-limit/applications/{application_id}/accept`

Подтверждает согласие клиента с условиями после положительного решения. Метод доступен только для заявления со статусом `approved` и требует повторной аутентификации.

## `GET /cards/{card_id}/credit-limit`

Возвращает состояние подключённого лимита:

```json
{
  "card_id": "card_204",
  "status": "active",
  "approved_limit": 7500000,
  "available_limit": 5000000,
  "outstanding_principal": 2500000,
  "minimum_payment": 125000,
  "currency": "RUB",
  "grace_period_days": 55
}
```

`minimum_payment` — рассчитанная сумма обязательного платежа. Она не должна быть меньше 30 000 копеек по правилу минимального платежа 300 ₽. Финальные значения и даты берутся из договора и актуального состояния счёта.

## `GET /cards/{card_id}/credit-limit/repayment`

Возвращает расчётный период, дату обязательного платежа, сумму основного долга, минимальный платёж, дату окончания льготного периода и сумму полного погашения по доступным условиям.

## `POST /cards/{card_id}/credit-limit/repayments`

Создаёт платёж в счёт задолженности. Обязательные поля: `amount`, `currency`, `source_account_id`. API возвращает операцию со статусом `created` или `processing`; зачисление подтверждается отдельным конечным статусом.

## `GET /product-communications/{communication_id}`

Возвращает содержание и статус продуктового сообщения для баннера, push, email, landing или SMS. Доступность коммуникации должна проверяться отдельно от продуктовой eligibility-проверки.

## Ошибки

```json
{
  "error": {
    "code": "requested_limit_out_of_range",
    "message": "Желаемый лимит должен быть от 30000 до 100000 рублей",
    "request_id": "req_01LUMEN7Y4"
  }
}
```

- `400` — неверная сумма, формат или состояние заявления.
- `401` — отсутствует или недействителен токен.
- `403` — карта не принадлежит клиенту или действие недоступно.
- `404` — карта, заявление или лимит не найдены.
- `409` — повторная отправка или конфликт состояния.
- `422` — заявление не соответствует предварительным условиям или требует действия клиента.
- `429` — превышен лимит запросов.

API не раскрывает внутренние правила кредитного решения. Неуспешная предварительная проверка, отказ и отсутствие предложения должны обрабатываться как разные состояния.
